# 项目备份 · 夜间同步与云端照片

labels: `ready-for-agent`

## Problem statement

大型项目或长期使用后，本地 `data/{项目号}/` 镜像（试验照片、数据表附件等）体积过大，占满磁盘；若仅依赖本地，误删或换机后进度与附件也易丢失。当前程序从公盘**单向**镜像到本地，编辑与 `project_state.json` 以本地为真相，**没有**写回公盘与释放本地空间的机制。报告员需要：白天在本地快速编辑；夜间在程序运行时将改动备份到公盘并清掉已确认上传的大文件；打开项目时仍能看到公盘已有照片（缩略图 + 云标记），并支持把个别公盘照片下载到正式相册继续改；JSON 因体积小可即时上公盘以便他人加载同一项目时看到排期（非实时协作，保存以后者为准）。

## Solution

保留本地 `data/{项目号}/` 为**白天工作区**（目录骨架始终存在；新照片/表/xlsx 写入本地路径），公盘 `source_path` 为**权威备份**。`project_state.json`：**保存明细时即时写入公盘**，并更新本地缓存供项目看板扫描。照片与数据表 xlsx：**程序运行且到达设定时刻**时增量上传到公盘；上传成功且校验一致（大小/mtime 或哈希）后**删除本地对应原文件**，不删目录。列表、预览、导出统一经 **合并资源解析器**：同一相对路径本地有文件则以本地为准（无云图标）；仅公盘有则显示缩略图 + 云图标；删除照片移入试验目录下系统保留的 **`备用/`** 文件夹（列表与导出排除，可拖回还原）。首次/从路径载入仍做**结构镜像**（目录 + 轻量文件），不全量拉回照片原图。预览/双击看大图从公盘或临时文件读取，**不为预览**再拷一份进相册目录；「下载到本地」为显式动作，写入正式相册路径。

## User stories

### 加载与 JSON

1. **US-01 打开项目读公盘 JSON**：作为报告员，我从「加载明细」历史选中某项目号后，程序按记录的 `source_path` 从公盘读取 `project_state.json`；若公盘文件比本地缓存新，提示是否用公盘版本覆盖当前编辑态（默认倾向用公盘，后者为准）。
2. **US-02 本地 JSON 缓存**：作为报告员，成功读取公盘 JSON 后，程序将一份副本写入 `data/{项目号}/project_state.json`，供项目看板与其它本地列表快速扫描，无需每次遍历公盘所有项目。
3. **US-03 从路径载入项目**：作为报告员，我通过「从路径加载项目 / 选择项目」指定公盘文件夹时，程序解析项目号、记录 `source_path`、拉取公盘 JSON（无则按现逻辑新建状态）、写入本地缓存，并执行结构镜像（目录 + 轻量文件，不拉回全部照片原图）。
4. **US-04 历史列表**：作为报告员，「加载明细」仍基于本地 `data/` 下已有缓存的项目（至少存在本地 `project_state.json` 或索引项）；选中后一律再按 US-01 与公盘对齐 JSON。
5. **US-05 保存明细即时上公盘**：作为报告员，我点击保存明细时，程序先将 `project_state.json` 写入公盘项目根，成功后再写本地缓存；公盘不可写时保存失败或标记待同步并提示（不静默丢 JSON）。
6. **US-06 公盘路径失效**：作为报告员，当 `source_path` 不可访问时，我仍可打开本地缓存 JSON 继续编辑，但提示公盘不可用；JSON 与照片的公盘同步排队重试。

### 目录骨架与结构镜像

7. **US-07 本地目录骨架**：作为报告员，夜间同步清文件后，本地仍保留与公盘同构的空目录（含 `1.接样组/`、`3.测试组/{Leg}-{试验}/` 下相册与 `数据表附件/`、`备用/` 等），以便白天新拖入照片/表无需现建路径。
8. **US-08 结构镜像**：作为报告员，首次从公盘载入时，程序创建缺失目录并复制轻量文件（如申请单 xlsx）；不复制已存在于公盘且体积大的照片原图与已上传的数据表 xlsx（除非用户显式下载）。

### 照片合并与云图标

9. **US-09 合并列表**：作为报告员，在试验照片栏中，某张图在合并视图中出现当且仅当：公盘或本地正式相册路径（非 `备用/`）中存在该相对路径，且未被移入 `备用/`。
10. **US-10 云图标**：作为报告员，合并列表中仅公盘有、本地无原文件的图片，缩略图带云标记；本地有原文件的（含新拖入未上传、或已从公盘下载到相册的）不带云标记。
11. **US-11 本地优先**：作为报告员，同一相对路径公盘与本地都有文件时，列表与导出以**本地文件**为准；夜间上传成功后按 US-16 清本地，此后该图显示为仅公盘（云标记）。
12. **US-12 新拖入照片**：作为报告员，我向正式相册拖入新照片时，文件立即写入本地相册路径，列表显示无云标记（可选「待上传」弱提示）；行为与 US-10 一致，不必与昨日公盘图在 UI 上完全相同，但应能区分「仅本地」与「仅公盘」。
13. **US-13 下载到本地相册**：作为报告员，我对仅公盘的某张图点击「下载到本地」时，程序将原图写入对应正式相册相对路径；之后该图无云标记，并参与 US-11 本地优先与夜间上传。
14. **US-14 预览不落盘**：作为报告员，我单击缩略图时，程序用中等清晰度预览（公盘或本地读入，或 `.thumbs` 缓存），**不**为此在 `3.测试组/.../` 相册目录新增副本。
15. **US-15 原图查看**：作为报告员，我双击（或等价「查看原图」）时，程序从公盘或本地打开原图；可使用系统临时目录，**不**写入正式相册路径。
16. **US-16 上传后清本地**：作为报告员，夜间（或手动触发）上传某文件到公盘且校验一致后，程序删除本地对应原文件；目录与 `.thumbs` 缓存保留；该图此后按 US-10 显示云标记。

### 删除与备用

17. **US-17 删除移入备用**：作为报告员，我在照片栏删除某张图时，程序将其**移动**到该试验目录下 `备用/`（若不存在则创建），而不是从公盘永久删除；列表与导出不再显示该图。
18. **US-18 备用不参与导出**：作为报告员，我生成 Word 时，程序不读取 `备用/` 内任何图片；`list_albums` 默认不把 `备用/` 当作普通照片相册列出。
19. **US-19 从备用还原**：作为报告员，我可将 `备用/` 内文件拖回正式相册文件夹，还原后重新出现在列表与导出中；变更随下次上传同步公盘。
20. **US-20 备用同步**：作为报告员，移入/移出 `备用/` 的变更在夜间增量上传中与普通文件一样同步到公盘（移动语义）。

### 夜间同步

21. **US-21 定时上传**：作为报告员，我可在偏好中启用夜间同步并设定时刻（如 22:30）；**仅当程序仍在运行**到该时刻时，对当前已打开或全部本地缓存项目执行增量上传。
22. **US-22 上传范围**：作为报告员，夜间任务上传本地相对公盘的新增/变更文件（含 `备用/` 内文件、数据表 xlsx、轻量文件），**不含**已被 US-17 移入备用且应从正式相册视图消失的路径；上传成功后执行 US-16。
23. **US-23 上传失败保留本地**：作为报告员，某文件上传失败时，本地原文件保留，状态栏或项目区显示失败项，下次定时或手动重试。
24. **US-24 手动立即同步**：作为报告员，我可手动触发「立即备份到公盘」，行为与夜间任务相同（不必等到定时）。
25. **US-25 同步状态可见**：作为报告员，我能在界面看到上次同步时间、进行中/失败摘要，且不抢占窗口焦点（后台线程）。

### 数据表

26. **US-26 数据表合并**：作为报告员，数据表附件列表与「打开编辑/刷新预览」经同一合并规则：本地 xlsx 优先；仅公盘有时可打开公盘路径或提示下载到本地后再编辑（与照片「下载到相册」类似，可选本期只做「打开公盘路径」）。
27. **US-27 数据表夜间上传**：作为报告员，白天在本地 `数据表附件/` 新建或修改的 xlsx 与照片一起在夜间上传；成功后清本地副本，索引仍在 JSON（即时已上公盘）。

### 导出

28. **US-28 导出读合并视图**：作为报告员，我导出 Word 时，试验照片从合并解析器取路径（本地原图或公盘原图临时读取），顺序与相册规则不变；不包含 `备用/`。
29. **US-29 导出不污染相册**：作为报告员，导出过程为嵌入 Word 而读的公盘原图，默认写入临时文件而非正式相册目录。

### 共享（非协作）

30. **US-30 他人加载同一项目**：作为报告员 B，我从公盘加载与 A 相同的项目号时，读到公盘上最新的 `project_state.json`（A 保存明细后即已上传），照片以缩略图 + 云标记展示公盘已有图；我不需要 A 的本地 `data/`。
31. **US-31 后者覆盖 JSON**：作为报告员，A 与 B 先后保存明细时，**以后写入公盘的 JSON 为准**；不做字段级合并、不加锁。
32. **US-32 照片滞后可接受**：作为报告员，A 白天新拖入的照片 B 在 A 的夜间上传完成前看不到；JSON 排期变更在保存后即对他人可见。

### 缩略图缓存

33. **US-33 缩略图缓存**：作为报告员，公盘照片的缩略图可缓存在 `data/{项目号}/.thumbs/`（或等价路径），避免每次列表都读公盘原图；清本地原图时不清必要缩略图缓存。

## Implementation decisions

* **权威副本**：公盘 `source_path` 为 JSON 与已上传附件的权威；本地 `data/{项目号}/` 为白天工作区 + 缓存 + 目录骨架。
* **JSON 双写顺序**：保存明细时 **先公盘后本地**（或公盘失败则整体失败并保留 dirty）；打开项目时 **读公盘**，与本地缓存比较 mtime/版本，公盘更新则提示重载。
* **主测试缝**：`src/io/project_assets.py`（或等价模块名）——给定 `local_root`、`remote_root`、相对路径：
  * 合并枚举照片/相册（排除 `备用/`）；
  * 解析单文件读路径（本地优先 → 公盘 → 错误）；
  * 判定是否「仅公盘」（云标记）；
  * 上传队列与校验后 purge 本地。
  * GUI、导出、`test_photos` 列表入口逐步改调此缝，避免双根逻辑散落。
* **辅测试缝**：`src/io/project_sync.py`——`incremental_upload`、`purge_verified`、`schedule_nightly`；与 Qt 定时器/UI 分离。
* **结构镜像**：复用/扩展 `incremental_copy`，增加「跳过大文件类型或超过尺寸阈值」策略；仍跳过从公盘覆盖本地 `project_state.json` 的旧规则改为「JSON 单独 API 读写公盘」。
* **备用文件夹**：固定名 `备用`，位于试验目录 `3.测试组/{Leg}-{试验}/备用/`；系统保留，`list_albums` 与 `list_photos` 默认排除；`TEMPLATE_ALBUMS` 与「全部重命名」不影响 `备用/` 内文件。
* **删除语义**：照片删除 = `shutil.move` 到 `备用/`；公盘同步后他机加载也看不到（因文件不在正式相册路径）。不做 JSON `photo_exclusions` 软删除表。
* **下载到本地**：显式 API `download_photo_to_album(relative_path)` 写入正式相册路径；与拖入等价，参与 upload。
* **预览/原图**：预览可用缩略图或中等尺寸；原图只读流或临时文件；禁止写入 `album_dir` 除非 US-13/US-12。
* **校验一致**：上传后 purge 前至少比对文件大小；可选 mtime 或 hash（大文件 hash 可配置）。
* **偏好**：`user_prefs.json` 增加 `nightly_sync_enabled`、`nightly_sync_time`（`HH:MM`）；可选 `nightly_sync_all_projects` vs 仅当前项目。
* **看板**：继续 `list_saved_projects` 扫本地 `data/*/project_state.json` 缓存；打开时再与公盘 JSON 对齐。
* **ADR 修订**：ADR-0001「照片以本地镜像为真相」在**合并视图**下扩展为「正式相册路径 + 公盘备份联合为真相；`备用/` 与 JSON 排除列表无关」；照片清单仍不进 JSON。
* **冲突**：JSON 仅最后写入公盘者胜；打开时提示公盘更新即可，不做三方合并。

## Testing decisions

* **好测试**：纯 `tmp_path` 下 mock `local_root` / `remote_root`，不断网、不绑 Qt 定时器（同步模块单测）；UI 测 1～2 条 smoke（云图标、保存 JSON 顺序）可选。
* **主缝覆盖**：
  * 仅公盘有图 → 合并列表含该项，`is_cloud_only` 为真；
  * 仅本地有图 → 列表含该项，非 cloud；
  * 两者同路径 → 读路径指向本地；
  * 移入 `备用/` → 正式列表不含，导出 resolver 不含；
  * 从 `备用/` 移回 → 重新出现；
  * 下载到相册 → 本地出现，cloud 假。
* **辅缝覆盖**：
  * `incremental_upload` 新文件出现在 remote；
  * upload + verify → 本地大文件删除，目录仍在；
  * upload 失败 → 本地仍在；
  * JSON save：remote 写入成功才写 local cache（或约定顺序可测）。
* **Prior art**：`tests/test_project_mirror.py`（incremental_copy）、`tests/test_test_photos.py`（相册路径）、`tests/test_data_tables.py`（附件路径）。
* **Done**：大项目白天本地编辑流畅；保存后公盘 JSON 更新；夜间上传后本地照片/xlsx 清掉但目录在； reopen 见云图 + 本地新图区分；删图进备用且导出不含；Word 导出含合并视图照片；看板仍能列本地缓存项目。

## Out of scope

* 实时多人协作、字段级合并、编辑锁、冲突分支。
* 程序未运行时的系统级定时任务（launchd / cron）。
* 公盘照片「仅 UI 隐藏仍导出」类软删除（改用 `备用/` 物理移动）。
* 自动迁移历史纯本地项目到公盘 JSON 权威（可手动从路径重载）。
* 备用文件夹自动清空 /  retention 天数策略。
* 数据表与 JSON 的保存即上传（数据表仍随夜间；仅 JSON 即时）。
* 上传进度「半透明→实体」动画（可选增强，非本期 done）。
* 双向同步公盘 → 本地全量镜像回灌（除 JSON 打开拉取与显式下载外）。

## Further notes

* 实现完成后应更新根 `CONTEXT.md` 词汇：**云端照片**、**备用**、**合并视图**、**夜间同步**、**目录骨架**。
* 与 `docs/specs/leg-scoped-test-dirs.md` 路径公式一致；`备用/` 与 `数据表附件/` 同级于试验目录下。
* `update.txt` 与主界面连接状态文案可增「公盘 JSON / 上次同步」。
* 若公盘 SMB 慢，列表应依赖 `.thumbs`，避免 N 次原图读取。
* 示例态（用户确认）：第一日 1–5 上传并清本地 → 第二日见 1–5 云图 → 下载 4 到本地 → 拷入 6–10 → 列表 1–3,5 云 + 4,6–10 本地 → 夜间上传 4,6–10 并清本地。手工清单见 [nightly-backup-manual-checklist.md](nightly-backup-manual-checklist.md)；自动化见 `tests/test_nightly_backup_smoke.py`。

## Agreed seams (binding)

| Seam | Responsibility | Tested behaviors |
|------|----------------|------------------|
| **Project assets** (`src/io/project_assets.py` 或等价) | 本地根 + 公盘根 → 合并枚举、解析读路径、云标记、排除 `备用/` | 仅公盘/仅本地/同路径优先、备用排除、导出列表一致 |
| **Project sync** (`src/io/project_sync.py` 或等价) | 增量上传、校验、purge 本地大文件、JSON 推公盘 | 上传成功删本地、失败保留、目录保留 |
| **JSON lifecycle**（可并入 sync 或 `project_mirror`） | 打开拉公盘、保存写公盘+缓存 | 公盘新于本地、保存顺序、失败不丢 dirty |

UI / Word / 照片面板 **不得** 手写 `if local exists else remote`；一律经 **Project assets**。
