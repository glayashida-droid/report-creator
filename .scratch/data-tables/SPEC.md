# 试验明细 · 数据表附件

labels: `ready-for-agent`

## Problem statement

试验明细的「样品与结果」目前只有样品编号与测试结论两列。报告员还需要把测量数据、工况记录等表格（往往已是 Excel，或要在 Excel 里填）附在同一试验下，并最终出现在 Word 报告的样品结果表之后。若在程序内重做一套伪 Excel（公式、拖角填充、合并单元格），成本高、易出 bug，也难与实验室已装的 Excel / WPS 对齐。

## Solution

在「样品与结果」中增加「添加数据表」：三种入口（上传现有 Excel / 自由编辑 / 模版）都落到该试验目录下的 **数据表附件** 文件夹里的一份 `.xlsx`，并在项目 JSON 里记 **数据表索引**（标题、相对路径、顺序）。编辑一律外开 Microsoft Excel（否则 WPS / 系统默认）；本程序只做列表、只读预览、刷新、导入样品编号与（后续）贴入报告。不在程序内实现单元格编辑器。

## User stories

1. **US-01 入口**：作为报告员，在试验明细「样品与结果」工具栏「生成」按钮右侧，我能看到「添加数据表」；每次点击都弹出三选一（上传现有 Excel / 自由编辑 / 模版）。
2. **US-02 上传 Excel**：选择「上传现有 Excel」后，我能挑选一个 `.xlsx`；程序取其**第一个工作表**的非空单元格**包围盒**（盒内空单元格保留），连同合并单元格等以该文件为准的内容，复制进本试验的数据表附件目录；列表标题为**文件名**（不含路径）。
3. **US-03 自由编辑**：选择「自由编辑」后，我能自定义标题；程序在数据表附件目录新建空工作簿，索引使用该标题，并可用外开方式编辑。
4. **US-04 模版（口子）**：选择「模版」后，我能从应用级目录 `templates/data_tables/` 中选一份已有文件（目录可先空）；程序将其复制到数据表附件目录，标题为文件名。选模版后「连带样品号」与完整模版库管理本期不做，只保留目录与复制入口。
5. **US-05 多表**：同一试验可添加多张数据表；每次「添加数据表」都走三选一，新表追加到列表末尾（顺序即报告顺序）。
6. **US-06 列表与抽屉**：样品/结果表下方只显示数据表**列表**（标题等）；展开某一项时用嵌套抽屉（形态对标试验标准里条件/要求那类「抽屉中的抽屉」），内为**只读预览**，不是程序内可编辑网格。
7. **US-07 外开编辑**：在某张数据表上我能「打开编辑」，用本机 Microsoft Excel 打开对应附件；若无 Excel 则尝试 WPS 或系统默认关联；都失败则提示无法打开。
8. **US-08 刷新预览**：从 Excel / WPS 改完回到本程序后，预览不会自动重读；我点击「刷新」后，程序再读盘并更新只读预览。
9. **US-09 导入样品编号**：在某张数据表上我能「导入样品编号」：程序改该 xlsx 的第一个工作表——若第 1 列在数据区无内容则写入第 1 列；若第 1 列已有内容则在左侧插入一列再写。样品编号从当前明细样品表读取，从工作表**第 2 行**起向下铺开（跳过表头行）。不要求与样品表后续改动自动同步。
10. **US-10 随项目保存**：数据表正文是附件目录中的 `.xlsx`；标题、相对路径、顺序记在该试验节点的数据表索引中，随项目 JSON 保存/加载。重开明细能看到原列表。
11. **US-11 报告位置（粗贴）**：**延期**至「Word 报告形成篇」。目标仍是样品结果表之后输出；保真贴法用例子对齐后再做。本期 tickets 不实现。
12. **US-12 无试验名不可用**：与试验照片类似，试验名称不可用时，不能创建或管理数据表附件目录。

## Implementation decisions

* **测试缝（唯一）**：`src/io/data_tables.py`（或同等模块）——数据表附件的添加（上传/空簿/模版复制）、导入样品编号、外开、刷新预览用的读盘快照、附件目录路径；与 GUI 分离。UI 与 Word 只调用此模块 + 节点上的索引字段。
* **磁盘路径**：本地镜像 `data/{项目号}/3.测试组/{试验名}/数据表附件/`。文件夹名固定为「数据表附件」，与照片夹「数据」不同。
* **模版目录**：应用仓库侧 `templates/data_tables/`（非项目内）；后续可再统一迁徙路径，本期写死此相对位置。
* **索引**：挂在 `TestNode`（或等价）上，随 `project_state.json` 持久化；至少含标题、相对路径（或可解析回绝对路径的字段）、顺序。xlsx 内容不以 JSON 再存一份。
* **与照片 ADR 的差异**：试验照片「磁盘为唯一真相、不进 JSON」；数据表是 **磁盘存 xlsx + JSON 存索引**（因需要稳定标题与报告顺序）。
* **上传语义**：只处理第一个工作表；以非空单元格包围盒为表范围，盒内空值保留；合并等格式以源文件为准复制进附件（实现上优先整文件复制再按需裁剪/或整表拷贝，但预览与「导入样品编号」按首表包围盒理解）。
* **外开优先级**：Microsoft Excel → WPS → 系统默认；失败则明确报错。
* **预览**：只读；合并与单元格值以刷新读盘结果为准；不要求与 Excel 窗口像素级一致。
* **不做程序内**：单元格编辑、拖角填充、公式求值 UI、筛选、图表。
* **完成勾**：数据表有无不影响试验完成勾与导出拦截（与照片一致），除非后续另定。

## Testing decisions

* **缝**：仅测数据表附件模块（无 UI）。
* **覆盖**：
  * 附件目录在给定 `project_root` + 试验名下创建/解析正确。
  * 上传：源文件进入附件目录；索引标题来自文件名；预览快照为包围盒且盒内空单元格保留；合并信息可读。
  * 空簿：自定义标题写入索引；文件存在且可外开路径可解析。
  * 模版：从 `templates/data_tables/` 复制；目录为空时选择入口可空/提示，不崩溃。
  * 导入样品编号：空第 1 列写入第 1 列；非空则左插列；从第 2 行起按当前样品 id 列表铺开。
  * 刷新：改磁盘后再读，快照更新（可用临时 xlsx 夹具，不依赖真开 Excel）。
* **外开**：可对「解析到的可执行/打开命令」做可注入的薄封装单测；不在 CI 里启动真实 Excel。
* **Done（本期）**：明细里能添加多张表、列表+抽屉预览、刷新、外开、导入样品编号、模版口子、保存重载索引仍在。Word 贴入整段延期，不算本期 done。

## Out of scope

* 程序内嵌 Excel 级编辑器（公式编辑 UI、拖角填充控件、筛选、图表）。
* Word 与 Excel **一模一样**的贴入（边框、列宽、颜色、合并的最终版式）——下一步用例子对齐。
* 模版库的管理界面、预置标准表内容、选模版后自动连带样品号的完整产品化（只留目录与复制口子）。
* 样品表变更后自动回写已有数据表。
* 数据表参与完成勾 / 导出拦截。
* 删除试验卡片时是否级联删除数据表附件目录（对照片：不删试验目录；本期不另定级联策略则可「不删目录」与照片一致）。
* 非 `.xlsx` 源格式、多工作表分别导入为多张附件的自动拆分。

## Further notes

* 词汇：**数据表附件** = 试验目录下存 xlsx 的文件夹；**数据表索引** = JSON 里该试验的表清单。避免与照片夹名「数据」混称。
* 明细「取消」是否回滚刚添加的附件文件：对照片 ADR 是不回滚磁盘；数据表建议同样「添加即落盘、取消不删文件」，索引若随保存才写入则取消可能留下孤儿文件——实现时与照片/保存交互对齐，并在实现票里写清。
* 同名文件再次上传时的去重/覆盖策略未在访谈中钉死；实现时选「自动加后缀不覆盖」更安全，若改覆盖需产品再确认。
* 像素级 Word 贴入单独立项；本 spec 的 US-11 只锁位置（样品结果表后）。

## Agreed seam (binding)

| Seam | Module | Tested behaviors |
|------|--------|------------------|
| 数据表附件 | `src/io/data_tables.py`（名可变，职责不可变） | 添加（上传/空簿/模版）、导入样品编号、外开入口、刷新用读盘快照、路径与索引协作 |

UI（`test_detail_dialog` 样品与结果区）与 Word（`word_engine` 样品结果表之后）不是测试缝，只消费上述模块。
